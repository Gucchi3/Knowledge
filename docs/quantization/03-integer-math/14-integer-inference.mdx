# 整数推論

> 量子化した層を、デバイス上で整数だけで動かす方法：積、INT32の和、バイアス、再量子化。

整数ハードウェアを持つデバイスでは、量子化したモデルを入力の画素から出力まで整数だけで動かせる。このページでは1つの層を追う。

## 考え方

実数値はそれぞれ、コード×スケール、つまり $r = S\,(q - Z)$ で表せる。これを線形層 $y = \sum_i w_i\, x_i + b$ に、対称な重みで代入する。

$$
y = \sum_i S_w q_{w,i} \cdot S_x (q_{x,i} - Z_x) + b = S_w S_x \Big( \underbrace{\sum_i q_{w,i}\,(q_{x,i} - Z_x)}_{\text{整数}} + \frac{b}{S_w S_x} \Big)
$$

和は純粋な整数演算である。スケールは $S_w S_x$ という1つの係数として外に出る。そのため、デバイスは整数の積を足し合わせ、スケールは最後に1回だけ扱えばよい。

## 1つの層の手順

1. **積和（MAC）。** 各入力のコードに重みのコードを掛け、積を**アキュムレータ**と呼ぶ広いレジスタに足し込む。
2. **バイアスを足す。** バイアスは和と同じスケール $S_w S_x$ の整数 $q_b = \mathrm{round}(b / (S_w S_x))$ として保存しておくので、アキュムレータにそのまま足せる。
3. **活性化。** ReLUは和を0以上に保つ。丸める前のアキュムレータに対して働く。
4. **再量子化。** 和のスケールは $S_w S_x$ と非常に小さい。次の層は、自分のスケール $S_y$ を持つ8ビットのコードを求める。[再量子化](15-requantization.md)は、和を整数の乗数とシフトで変換し、出力形式に丸める。

出力のコードは次の層に渡り、同じ手順を繰り返す。

## アキュムレータが32ビットである理由

8ビットのコードどうしの積には最大16ビットが要る。層は多数の積を足し合わせる。たとえば入力64チャネルの3×3畳み込みは576個を足す。足す積の数が2倍になるごとに、約1ビットずつ多く必要になる。32ビットのアキュムレータなら最大の大きさの積を10万個以上足せるので、ほとんどすべての層をカバーできる。INT8推論がINT32の和とINT32のバイアスを使うのはこのためである。

## 最後の層

最後の層は再量子化を省き、INT32の和をそのままロジットとして返すことが多い。和は正確であり、最大のロジットを探すのにスケールは要らない。
