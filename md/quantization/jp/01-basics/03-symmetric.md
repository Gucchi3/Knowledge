# 対称量子化

> ゼロ点を0に固定する置き方。整数演算は単純になるが、使われないコードが出ることがある。

対称量子化では、ゼロ点を0に固定し、表せる範囲を0の左右に同じ幅で取る。

## 決め方

データの絶対値の最大を $`R`$ とし、それに最大のコードを割り当てる。

```math
R = \max(|r_{min}|,\ |r_{max}|), \qquad S = \frac{R}{q_{max}}, \qquad Z = 0
```

ゼロ点が0なので、量子化も逆量子化もゼロ点を気にせずに済む。

```math
q = \mathrm{clip}\left(\mathrm{round}\left(\frac{r}{S}\right),\ -q_{max},\ q_{max}\right), \qquad \hat{r} = S\,q
```

INT8なら $`q_{max} = 127`$ である。

## よく使われる理由

ゼロ点が0だと、コード同士の積に補正が要らない。層は入力のコードと重みのコードを掛けて足し合わせるが、その和は、実数の和を2つのスケールで割ったものにそのまま一致する。

```math
\sum_i r_{x,i}\, r_{w,i} \approx S_x S_w \sum_i q_{x,i}\, q_{w,i}
```

デバイスの整数演算がそのぶん小さく、速くなる。重みはたいてい0の周りに左右均等に分布しているので、重みには対称量子化を使うのが普通である。

## 弱点

データが0を中心にしていないと、使われないコードが出てくる。たとえば、−400から1000までのデータを考える。

- $`R = 1000`$ なので、$`S = 1000 / 127 \approx 7.87`$ になる。
- 表せる範囲は−1000から1000だが、−400より小さい値は一つもない。
- −128から−52までのコード（全体の約30%）は、出てこない値のために取ってあることになる。

使えるコードが減れば目盛りは粗くなり、丸め誤差も大きくなる。この無駄をなくすのが[非対称量子化](04-asymmetric.md)である。

## 負にならないデータ

ReLUの出力は負にならない。これを符号付きの形式で表すと、負の側のコード、つまり半分が無駄になる。そこで、ゼロ点は0のまま、**符号なし**の形式を使う。

```math
S = \frac{r_{max}}{255}, \qquad q \in [0, 255] \quad \text{(UINT8)}
```

これなら256個のコードをすべて実際の値に使え、演算も上と同じく単純なままである。カメラの画像も同じ形をしている。画素の値はもともと $`S = 1/255`$ のUINT8のコードになっている。

## −128を使うか、−127で止めるか

INT8のコードは−128から127までなので、0を中心にすると負の側に1つだけコードが余る。多くの形式（たとえばTFLiteの重み）は−127から127だけを使い、範囲を厳密に左右対称にする。−128から127をそのまま使い、対称なスケールでは単に−128に届かないとする形式もある。

> [!NOTE]
> どちらでも動くが、学習時とデバイスでは同じ方を使う必要がある。
