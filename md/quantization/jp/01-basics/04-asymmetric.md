# 非対称量子化

> ゼロ点を動かして、範囲をデータに合わせる置き方。コードの無駄はなくなるが、整数演算が少し増える。

非対称量子化では、データの最小値から最大値までを、コードの範囲全体に割り当てる。ゼロ点はもう0とは限らず、実数の0が来る位置に合わせて動く。

## 決め方

```math
S = \frac{r_{max} - r_{min}}{q_{max} - q_{min}}, \qquad Z = \mathrm{round}\left(q_{min} - \frac{r_{min}}{S}\right)
```

量子化と逆量子化の式は、[スケールとゼロ点](02-scale-zero-point.md)で見たものと同じである。

```math
q = \mathrm{clip}\left(\mathrm{round}\left(\frac{r}{S}\right) + Z,\ q_{min},\ q_{max}\right), \qquad \hat{r} = S\,(q - Z)
```

## 同じデータで比べる

[対称量子化](03-symmetric.md)で使った−400から1000までのデータを、INT8で量子化してみる。

- $`S = 1400 / 255 \approx 5.49`$
- $`Z = \mathrm{round}(-128 + 400 / 5.49) = \mathrm{round}(-55.1) = -55`$
- −400は $`\mathrm{round}(-72.9) - 55 = -128`$ に、1000は $`\mathrm{round}(182.1) - 55 = 127`$ になる。

今度はすべてのコードが使われる。目盛りの間隔は7.87から5.49に縮み、丸め誤差は約30%小さくなる。

## 代わりに増える計算

ゼロ点が0でないと、コードを掛ける前にゼロ点を引いておく必要がある。入力 $`x`$ が非対称、重み $`w`$ が対称な層では、次を計算することになる。

```math
\sum_i q_{w,i}\,(q_{x,i} - Z_x) = \sum_i q_{w,i}\, q_{x,i} \;-\; Z_x \sum_i q_{w,i}
```

右辺の第2項は、重みと $`Z_x`$ だけで決まる。つまり出力チャネルごとの定数なので、前もってバイアスに足し込んでおけば、実行時には何も増えない。

ところが重みも非対称にすると、項がもう1つ増える。

```math
\sum_i (q_{w,i} - Z_w)(q_{x,i} - Z_x) = \sum_i q_{w,i}\, q_{x,i} - Z_x \sum_i q_{w,i} - Z_w \sum_i q_{x,i} + n\,Z_w Z_x
```

$`Z_w \sum_i q_{x,i}`$ は入力によって変わるので、前もって計算しておけない。デバイスは入力のたびにこれを計算し直すことになる。

> [!TIP]
> 活性化を非対称にする場合でも重みは対称にしておくことが多いのは、このためである。

## 使いどころ

- 0を中心とせず、しかも負の値もとる活性化。たとえば、ReLUを通らない層の出力や、GELUの出力。
- 4ビット以下のようにビット幅がとても小さく、コードを1つも無駄にしたくない場合。

ReLUの後のように値が負にならないなら、ゼロ点を使わなくても[符号なしの対称形式](03-symmetric.md#負にならないデータ)で同じ効果が得られる。
