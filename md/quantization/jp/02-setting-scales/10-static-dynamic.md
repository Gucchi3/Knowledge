# 静的スケールと動的スケール

> スケールを推論の前に決めてしまうか、入力が来るたびに測るか。

重みのスケールは、学習が終われば決まる。厄介なのは活性化のスケールで、活性化は入力が変わるたびに変わってしまう。扱い方は2通りある。

| | 静的 | 動的 |
|---|---|---|
| 活性化のスケールを決める時期 | 推論の前に1回 | 推論中、入力が来るたび |
| 実行時の処理 | なし | 範囲を測り、スケールを計算する |
| 入力の変化への追従 | 弱い | 強い |
| よく使われる場面 | 組み込み機器 | サーバ、大規模言語モデル |

## 静的スケール

サンプルデータで測るか（[キャリブレーション](11-ptq.md)）、[QAT](12-qat.md)の中で決めるかして、スケールを固定しておく。推論では、各層が固定のスケールをそのまま使う。デバイスではスケールが固定の乗数とシフト量になるので、実行時の計算は整数の乗算、加算、シフトだけで済む。

> [!WARNING]
> スケールを決めたときのデータと大きく違う入力が来ると、値がクリップされたり、粗く丸められたりすることがある。

## 動的スケール

デバイスが実行中に活性化テンソルの範囲を測り、そこからスケールを計算する。スケールはいつも、その時の入力にぴったり合う。

そのかわり手間がかかる。量子化する前にテンソルの最大値を探す必要があり、データをもう一度読み直すことになる。さらに、新しいスケールを乗数とシフト量に変換するのに除算が要る。時間も電力も食うので、組み込み機器では静的スケールを使うのが普通である。

## 動的スケールが欲しくなる層

attentionのスコアのように、入力によって値の大きさががらりと変わるものもある。こうした値には、入力ごとに測ったスケールを使った方が精度を保ちやすい。NEQを使った[SimA attention](../04-quantized-layers/21-sima-attention.md)では、これを整数演算だけで実現しており、デバイスは各テンソルのスケールを整数の除算で求める。
