# 共有スケール

> 複数のテンソルにわざと同じスケールを持たせ、デバイスが整数のまま足し算できるようにする。

前のページで見たとおり、スケールの違う2つのテンソルを足すには、乗数とシフトで片方または両方のスケールを揃える手間がかかる。足し合わせるテンソルに初めから同じスケールを持たせておけば、この手間はなくなる。これが共有スケールである。

## 2つのテンソルを足すときの問題

残差加算では $`y = a + b`$ を計算する。コードを $`q_a`$、$`q_b`$、スケールを $`S_a`$、$`S_b`$ とすると、次のようになる。

```math
y = S_a\, q_a + S_b\, q_b
```

$`S_a \ne S_b`$ なら、コードをそのまま足すことはできない。少なくとも一方を乗数とシフトで変換してから足す必要がある（[残差加算](18-residual-add.md)）。

$`S_a = S_b = S`$ なら、足し算はこれだけで済む。

```math
q_y = q_a + q_b
```

あとは形式の範囲に収めるだけで、乗算もシフトも丸めも要らない。

## 残差ストリームでスケールを共有する

Transformerのブロックは、各分岐の出力を残差ストリームに足していく。まず $`x + \mathrm{attention}(x)`$、次に $`x + \mathrm{MLP}(x)`$ である。スケールを共有する場合は、ブロックの中のストリーム全体を1つのスケールで表す。対象は次のとおりである。

- ブロックへの入力
- attention分岐とMLP分岐の出力
- 2回の足し算の結果

各分岐は、最後の出力をこの共有スケールに再量子化する。この再量子化は、分岐の最後の畳み込みと同じ段階でどのみち行うので、手間は増えない。こうすると2回の足し算は、飽和付きのただの整数加算になる。次のブロックでは、また別の共有スケールを使う。

## 共有スケールの決め方

共有スケールは、対象のテンソルすべてを一度に表せなければならないので、その中でいちばん範囲の広いテンソルに合わせることになる。学習中は、パスごとに見た最大の範囲の移動平均を取っておく。

> [!NOTE]
> 範囲の狭いテンソルは、そのぶん目盛りが粗くなる。足し算をただにする代わりに払う代償である。
